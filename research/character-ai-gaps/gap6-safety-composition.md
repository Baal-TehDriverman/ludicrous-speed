### arXiv:2606.12797 — The Containment Gap: How Deployed Agentic AI Frameworks Fail Public-Facing Safety Requirements
URL: https://arxiv.org/abs/2606.12797
Authors: Md Jafrin Hossain, Mohammad Arif Hossain, Weiqi Liu, Nirwan Ansari
Categories: Artificial Intelligence

**Claim:** Audits whether deployed agentic AI frameworks provide architectural-level structural safety guarantees, using six containment principles derived from a compositional model of agentic architectures. Finds no native compliance in LangChain, AutoGPT, or OpenAI Agents SDK — memory integrity (a defense against one of the most prevalent vulnerability classes) is absent from all three. Empirically validates: a single memory-poisoning write in a simulated LangChain government-benefits agent induces persistent targeted corruption across all seeds/backends, increasing wrongful denial rate for targeted applicants to 88.9%; under a complex five-factor policy, the same attack preserves aggregate accuracy while increasing targeted wrongful denials by 3.5x, evading standard monitoring. Introduces two lightweight containment mechanisms — a memory integrity validator and a policy gate — which eliminate both attack vectors with sub-millisecond overhead (<0.2ms per call).

**Closes gap:** partially — this is the most direct audit yet of whether real-world agent frameworks satisfy compositional safety principles, and the answer is a uniform NO. Its six containment principles are a ready-made checklist for gap-6's composition guarantees, and the memory-integrity validator is a concrete instance of the per-layer-fallback pattern. But it audits existing frameworks rather than proposing a new composition architecture, and its two mechanisms are specific to memory/tool calls, not to continuous affective influence or generative-module disagreement.

**Implementation note:** Use the six containment principles as the acceptance criteria for a pattern-B stack's composition architecture: each module (dialogue, affect, social learning) must satisfy containment at its boundary, and the whole stack must satisfy compositional containment across boundaries. The memory-integrity validator maps to checking that a module's state writes are consistent with its declared capabilities before admission. The 3.5x evasion-by-aggregate-accuracy result is the quantitative argument that per-module monitoring is insufficient — pair with Hu & Wang's observability-boundary proof (2607.11751) for the theoretical backing. Falls short: no arbitration protocol for when two containment principles disagree, no attribution of which module drove which composed output.

### arXiv:2603.13247 — ILION: Deterministic Pre-Execution Safety Gates for Agentic AI Systems
URL: https://arxiv.org/abs/2603.13247
Authors: Florin Adrian Chitan
Categories: Artificial Intelligence, Cryptography and Security

**Claim:** A deterministic execution gate for agentic AI systems, employing a five-component cascade architecture (Transient Identity Imprint, Semantic Vector Reference Frame, Identity Drift Control, Identity Resonance Score, Consensus Veto Layer) to classify proposed agent actions as BLOCK or ALLOW without statistical training or API dependencies. Requires zero labeled data, operates in sub-millisecond latency (143 microseconds mean), and produces fully interpretable verdicts. Evaluated on ILION-Bench v2 (380 test scenarios, eight attack categories, 39% hard-difficulty adversarial cases): F1 = 0.8515, precision = 91.0%, false positive rate = 7.9%. Outperforms Lakera Guard (F1 = 0.8087), OpenAI Moderation API (F1 = 0.1188), and Llama Guard 3 (F1 = 0.0105) — existing text-safety infrastructure systematically fails on agent execution safety due to fundamental task mismatch.

**Closes gap:** partially — this is the most detailed deterministic-gate design found, with a five-component cascade that is itself a layered safety architecture (each component is a mini-gate). Its fully interpretable verdicts are exactly the audit property gap 6 demands: every BLOCK/ALLOW decision is reconstructable. But it gates single-agent tool calls, not multi-module generative composition; there is no notion of an affect module, no arbitration between disagreeing layers, and the cascade is a single chain rather than a composition of independent modules.

**Implementation note:** The cascade architecture — multiple independent gate components whose verdicts merge into a final BLOCK/ALLOW — is the closest found analog to gap-6's desired composition pattern. For a character stack: map each gate component to a safety layer (semantic policy, scope check, behavioral consistency, resonance with character profile, veto override), each producing an interpretable signal, and merge them into a final admit/reject. The sub-millisecond latency means it can run inline on every state write. Falls short: the cascade is trained/calibrated as a unit, not composed from independently certified layers; replacing one component requires re-validating the whole cascade. No cross-module attribution.

### arXiv:2605.18988 — Surviving the Unseen: Predictive Defense for Novel Multi-Turn Multimodal Attacks
URL: https://arxiv.org/abs/2605.18988
Authors: Doohee You
Categories: Cryptography and Security, Artificial Intelligence

**Claim:** Formulates safety verification as a dynamic survival prediction and trajectory dynamics problem. Proposes TRIAD (Triple-tier Anomaly Defense): maps multimodal multi-turn conversational flow as a continuous trajectory, integrates structural anomaly detection (covariance shifts via Ledoit-Wolf regularized Mahalanobis distance), topological trajectory acceleration to differentiate benign exploration from malicious drift, all integrated into a time-varying Cox Proportional Hazards model via a Bayesian HMM feedback loop. Theoretical analysis demonstrates the framework provides a mathematically bounded expected time-to-failure under adversarial perturbations.

**Closes gap:** addresses adjacent problem — it predicts when a multi-turn trajectory will become unsafe rather than detecting individual unsafe actions, which is the temporal analogue of gap-6's composition problem (predict when composed state becomes unsafe). But it monitors conversational trajectories, not module composition; there is no notion of which module is driving the trajectory, and the framework assumes a single generative agent rather than multiple composed modules.

**Implementation note:** The trajectory-level predictive framing is liftable to character safety: instead of asking "is this module's output safe?", ask "is the composed character-state trajectory heading toward an unsafe attractor?" The topological-acceleration signal (detecting drift vs. exploration) could flag when an affect module is continuously biasing the character's state in a dangerous direction — the temporal signature of the continuous-affect problem that no prior paper addresses. Falls short: the framework is single-agent, so it cannot attribute trajectory drift to a specific module, and the theoretical bound holds only under the model's assumptions about adversarial perturbation structure.

Categories: Information Retrieval, Artificial Intelligence

**Claim:** Studies trajectory-to-evidence conversion: asks what a completed research process has actually established. A context-isolated generate–verify–repair process checks artifacts for evidence violations before release. After execution, validity and attribution checks consolidate evidence across rounds, qualify intervention-level claims as actionable repairs, diagnostic guards, or withheld findings, and preserve admitted claims as auditable records with explicit provenance and applicability boundaries. **Closes gap:** addresses adjacent problem — it does not do runtime safety gating, but it solves a harder version of the audit-trail problem gap 6 names: not just "which module drove which action" but "which claim from which round actually survives evidence qualification." The attribution checks that consolidate evidence across rounds are the missing piece for multi-turn composed character systems where a decision may reflect contributions from several earlier turns.

**Implementation note:** For a pattern-B stack with persistent character state: log every module's contribution as a "claim" with explicit provenance and applicability boundaries, then run post-hoc attribution checks that qualify each claim as "actionable" (fed forward), "diagnostic" (flagged for review), or "withheld" (suppressed). The non-monotonicity finding is a warning: a character's safety posture may degrade over a long session even when each individual turn passed its gate — the audit trail must support retroactive claim invalidation. Falls short: validated on research-experiment trajectories, not generative character emission; no runtime gate, only post-hoc qualification.

### arXiv:2512.00520 — Toward a Safe Internet of Agents
URL: https://arxiv.org/abs/2512.00520
Authors: Juan A. Wibowo, George C. Polyzos
Categories: Multiagent Systems

**Claim:** Principled guide addressing architectural vulnerability sources for interconnected AI agent systems. Offers a framework through bottom-up deconstruction, analyzing each component as a dual-use interface where capability expansion creates attack surface growth. Three tiers: (1) Single Agents — risks in models, memory, design patterns, tools, guardrails; (2) Multi-Agent Systems — collective behavior, communication, verification, system guardrails; (3) Interoperable Multi-Agent Systems — standardized protocols, agent registration/discovery, resource vetting, governance. Central principle: agentic safety must be co-designed with capability as a fundamental architectural property.

**Closes gap:** addresses adjacent problem — it is a taxonomy and design guide, not a mechanism. But its three-tier decomposition (single → multi → interoperable) is the most systematic mapping of the composition-safety landscape found, and the co-design principle ("safety must be co-designed with capability as a fundamental architectural property") is the clearest statement of gap-6's underlying thesis. Its analysis of Multi-Agent Systems tier names verification and system guardrails as first-class concerns.

**Implementation note:** Use the three-tier framework to scope a pattern-B stack's safety architecture: single-module safety (each net has its own guardrails), multi-module safety (orchestration contract, inter-module communication integrity), and interoperable safety (if the character interacts with other characters or external systems). The co-design principle is the design rule: never add a new capability (e.g., a new affect module) without simultaneously specifying its safety contract. Falls short: it is a position/taxonomy paper with no implementation, no numeric evaluation, and no mechanism for the arbitration or attribution sub-gaps.
